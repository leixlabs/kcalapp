# 餐次级营养评价设计

> 状态：已完成（2026-09-30）
> 
> 目标：支持一餐分多次拍照记录，同时不增加首页操作复杂度。

## 已确认的产品判断

1. **餐次自动分组保持不变。** 记录仍按时间自动归入早餐、午餐、晚餐或加餐；首页现有的餐次重量与 kcal 汇总继续作为主视图。
2. **不新增“加入本次早餐”按钮或“进行中餐次”状态。** 对用户而言，每一次拍照都是一次普通记录；系统在保存时按既有时间规则归组。
3. **食物记录仍保留为独立条目。** 每次拍照产生的图片、识别结果和编辑历史可单独查看、修改或删除，方便纠错与追溯。
4. **AI 营养评价的归属改为餐次。** 单条记录页不再把“营养师评价”作为主要内容；早餐/午餐/晚餐/加餐拥有一份基于全部已归组食物的汇总评价。
5. **首页显示餐次评价摘要。** 摘要控制在 1–2 行；点击早餐卡片后查看完整评价和组成食物。
6. **评价在后台刷新。** 保存食物不等待评价请求；营养汇总立即更新，评价随后替换。
7. **微量营养素只保留核心项。** 不再要求模型逐项估算全部微量元素，以减少模型输出、避免虚假的精确感，并降低详情页的信息密度。

## 推荐的信息结构

```text
一天
└─ 早餐（时间规则自动归组）
   ├─ 汇总：640 g · 719 kcal · 三大营养素
   ├─ 餐次级 AI 营养评价
   └─ 食物记录
      ├─ 中式蒸包早餐（照片、识别结果、食材明细）
      ├─ 水煮蛋
      ├─ 脱脂牛奶
      └─ 新鲜青橙
```

这使“分多次拍照”自然成为同一餐次下的多条记录，而非需要用户手动合并的特殊流程。

## 首页设计

早餐卡片维持现有汇总能力，并增加/强化评价入口：

- 标题：`早餐`
- 汇总：`640 g / 719 kcal`
- 辅助信息：`4 项记录 · 最后记录 09:36`
- 内容：食物列表与缩略图
- 卡片底部或展开区：`早餐营养评价` 摘要；点击查看完整评价

评价应属于早餐卡片，而不是某个如“新鲜青橙”的条目。这样用户不会误以为“只吃一个橙子”的分析代表整顿早餐。

## 食物详情页调整

原本位于单条记录详情中的“营养师评价”替换为轻量提示：

> 已计入早餐（共 719 kcal）。早餐营养评价会根据全部食物生成。

点击可跳转或展开该早餐的评价。单条详情页继续展示：图片、识别出的食材、该条记录的营养数据和可编辑能力。

## 评价刷新策略

### 触发条件

以下任一变化发生后，使所属餐次的评价失效：

- 新增一条已识别并保存的食物记录；
- 编辑或删除某条记录；
- 调整记录所属的餐次；
- 因时间/日期调整而进入或离开该餐次。

### 交互与状态

采用“**保存后自动后台刷新，评价可短暂显示更新中**”的策略：

1. 用户保存食物记录后，首页的重量、kcal 和宏量营养素立即重新汇总；
2. 早餐评价区域显示 `正在根据 4 项食物更新评价…`，保留上一次评价但标记为“待更新”，避免空白；
3. 新评价返回后原位替换，并标注 `基于 4 项食物`；
4. 若生成失败，保留上一次评价或展示“暂未生成评价”，提供明确的 `重新生成` 操作，不阻塞记录保存。

不建议每新增一项就强制用户等待评价完成，也不建议为了节省请求而长期沿用明显过期的评价。

## 微量营养素精简策略

当前接口强制模型为每一种食材估算 11 项矿物质和 13 项维生素。这不仅使响应冗长，也会诱导模型对难以从图片可靠推断的项目给出貌似精确的数字。

### 推荐的首发核心集

| 类别 | 保留项 | 理由 |
|---|---|---|
| 矿物质 | 钙、铁、钠 | 对奶类/豆制品、肉蛋与高盐加工食品的饮食提示有直接意义；也适合在餐次评价中引用。 |
| 维生素 | 维生素 A、维生素 C、维生素 D、维生素 B12 | 分别覆盖深色蔬果、果蔬、日照/强化食品、动物性食品等常见且用户易理解的饮食线索。 |

产品默认只展示模型有把握提供的上述项目；不把“未估算”显示成 `0`。其余微量元素不进入本次识别请求，也不在常规详情页展示。

### 接口与提示词要求

- 不再使用按固定顺序填满 24 个数字的数组。改为**可选的具名字段**，例如 `{"calcium_mg": 120, "iron_mg": 1.1, "vitamin_c_mg": 35}`；模型无法合理估算的字段直接省略。
- Prompt 明确：`仅在对核心微量营养素有合理依据时返回估算；不要为了补齐字段猜测或填 0。`
- Schema 也必须同步改为上述可选字段；**只改 prompt 不足够**，因为现有 JSON Schema 对每个食材强制要求 11+13 个数值数组。
- 历史数据和手动编辑数据保持兼容；仅改变新的 AI 识别输出与默认展示，不删除已保存的字段。

后续若用户明确需要更完整的膳食分析，可在“高级营养详情”中按需触发，而不成为每次拍照识别的默认成本。

## 评价内容与文案边界

- 评价输入使用整个餐次的食材和营养合计，而非最新照片。
- 评价首句应描述餐次整体，例如：`这份早餐蛋白质充足，但蔬菜水果偏少。`
- 明示 `AI 生成，营养估算仅供饮食记录参考`，避免医疗或诊断式措辞。
- 对只有一条记录的早餐，餐次评价与单条场景的结果看似相同，但数据模型和文案仍保持餐次级，后续加食物时可无缝更新。

## 实施前唯一待确认项

核心微量营养素暂按“钙、铁、钠、维生素 A/C/D/B12”设计。若希望更贴近中国居民日常饮食提示，也可将维生素 D 或 B12 替换为锌；确认后再同步调整数据结构、LLM Schema、Prompt 和详情展示。

- 已完成：识别 Prompt 与 JSON Schema 从 24 个强制微量营养素数值改为 7 个核心具名字段；未知字段用 `null` 表示。
- 已完成：识别结果页和食物详情页只展示核心项；已有记录的旧数据仍可读取，但默认不再展示非核心项。
- 已完成：新增 `meal_reviews` 独立存储（`date + meal_type` 主键）、`MealReviewDao` 与 `mealReviewProvider`；餐次评价不再写入单张食物记录的 `nutrition_review` 字段。
- 已完成：餐次评价后台生成集中在 `MealReviewController`，在识别完成、保存/编辑/删除记录、调整餐次后自动触发；刷新期间保留上一次评价内容，失败不阻塞记录保存。
- 已完成：首页餐次卡片显示评价摘要（含「基于 N 项食物」标注），点击打开完整评价底部弹层（含组成食物与「重新生成」）。
- 已完成：单条记录详情页的「营养师评价」替换为「已计入某餐次」轻量提示，点击查看该餐次完整评价。
