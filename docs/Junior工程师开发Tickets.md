# Junior 工程师开发 Tickets

> 适用版本：MVP  
> 配套设计：[产品与架构设计.md](产品与架构设计.md)  
> 使用方式：每个 Ticket 应由一位负责人独立完成、提交合并请求，并经代码评审后关闭。除标记“依赖/风险”的 Ticket 外，不应把多个 Ticket 合并为一个大任务。

## 0. 统一开发约定

### 完成定义（所有 Ticket 通用）

- 代码通过格式化、静态检查和现有测试。
- 新增业务逻辑具备单元测试；有 UI 的任务至少覆盖 loading、空数据、错误三种状态中适用的状态。
- 不提交 API Key、真实餐食图片、设备路径、个人配置或构建产物。
- 文案使用中文，所有可见交互具有语义标签和不小于 44px 的触控区域。
- iOS/Android 通用业务代码不得直接依赖某平台的实现；平台能力通过既定 Gateway 接口调用。
- 完成后在 PR 描述中附上：实现说明、测试结果、截图/录屏（如有 UI）、已知限制。

### Ticket 状态建议

`Backlog → Ready → In Progress → Code Review → QA → Done`

### 依赖图

```text
项目壳与规范（T01）
  ├─ 领域模型（T02）→ SQLite 基础（T03）→ Repository（T04）
  │                              ├─ 目标设置（T05）→ 日汇总（T06）→ 首页（T07）
  │                              └─ 餐食编辑（T08）→ 餐次卡片（T09）→ 日历（T10）
  ├─ 安全存储（T11）→ LLM 配置（T12）→ 连通性测试（T13）
  ├─ 图片网关（T14）→ 图片预处理（T15）→ LLM 解析（T16）→ AI 确认页（T17）
  └─ 导出（T18）/数据清除（T19）/质量收尾（T20）
```

## Sprint A：可离线手动记餐

### T01｜建立 Flutter 工程骨架与开发规范

- **优先级：** P0
- **预估：** 1–2 人日
- **前置：** 无
- **目标：** 建立可在 iOS 与 Android 编译运行的 Flutter 工程骨架，并预留鸿蒙构建说明。
- **实现范围：**
  - 配置 Dart/Flutter lint、格式化、基础目录（`app`、`core`、`features`、`data`、`platform`）。
  - 建立启动入口、应用主题、命名路由/声明式路由的最小实现。
  - 建立 `README`：本地运行、测试、构建、环境变量原则；不写真实服务商密钥。
  - 配置最小 CI：格式检查、静态检查、单元测试。
- **不包含：** 业务页面、数据库、LLM 调用、鸿蒙真正适配。
- **验收标准：**
  - 空壳 App 能在 iOS Simulator 和 Android Emulator 启动。
  - CI 在无警告情况下通过；目录中不存在硬编码密钥。
  - README 足以让另一位工程师启动项目。
- **测试：** `flutter analyze`、`flutter test`、两端启动截图。

### T02｜定义核心领域模型与营养计算器

- **优先级：** P0
- **预估：** 1.5 人日
- **前置：** T01
- **目标：** 用纯 Dart 定义餐食、食材、营养、每日目标等不可依赖 UI 或数据库的模型。
- **实现范围：**
  - `Nutrition`：kcal、carbsG、proteinG、fatG；加法、乘份数、非负校验、展示格式化。
  - `FoodItem`、`Meal`、`DailyGoal`、`MealType`（早餐/午餐/晚餐/加餐）。
  - `Meal` 从食材聚合总营养，禁止把外部 AI 返回的总计当作最终保存值。
  - 规定热量显示为整数、克数最多一位小数的统一规则。
- **不包含：** JSON 网络解析、数据库表、页面。
- **验收标准：**
  - 修改任一食材的数值或份数后，餐食总热量和三大营养素正确变化。
  - 负数、NaN、Infinity 等异常输入不会进入有效模型。
- **测试：** 至少覆盖空餐食、多个食材、小数、份数、异常值、格式化共 10 个断言场景。

### T03｜建立本地 SQLite 数据库与迁移框架

- **优先级：** P0
- **预估：** 2 人日
- **前置：** T01、T02
- **目标：** 创建本地数据库，并具备未来升级时安全迁移数据的能力。
- **实现范围：**
  - 创建 `daily_goals`、`meals`、`food_items`、`app_settings` 数据表和索引。
  - `meals` 与 `food_items` 建立外键/级联策略；设计 `created_at`、`updated_at`、软删除或 Undo 所需字段。
  - 创建数据库版本及迁移入口；开发环境可安全重建测试库。
  - 提供仅供测试使用的内存/临时数据库配置。
- **不包含：** Repository 查询接口、数据导入导出。
- **验收标准：**
  - 新建库可建表；模拟从上一版本升级时，已有记录不丢失。
  - 删除一条餐食时关联食材按设计处理，不产生孤儿记录。
  - 日期与时间存储采用统一时区规则（建议本地日期 + UTC 创建时间），并有注释说明。
- **测试：** 建库、插入、迁移、级联删除/软删除各至少一项自动化测试。

### T04｜实现 Meal Repository（餐食本地读写）

- **优先级：** P0
- **预估：** 2 人日
- **前置：** T02、T03
- **目标：** 为上层提供稳定的餐食新增、查询、更新、删除接口。
- **实现范围：**
  - `saveMeal`：餐食与食材在一个数据库事务中保存。
  - `getMealsByDate`、`getMealById`、`updateMeal`、`deleteMeal`。
  - 返回领域模型而不是数据库行对象；处理食材排序。
  - 写入/更新时使用 T02 的聚合结果重算营养总计。
- **不包含：** UI、图片实际存储、跨日期复制。
- **验收标准：**
  - 保存后重新读取，餐次、名称、食材、营养值和排序一致。
  - 更新食材后总计正确；事务中任一步失败不会留下半条餐食。
  - 按本地日期查询，不会因 UTC 跨日把记录归错日期。
- **测试：** CRUD、事务回滚、同日/跨日查询、食材排序。

### T05｜每日目标设置与持久化

- **优先级：** P1
- **预估：** 1.5 人日
- **前置：** T02、T03
- **目标：** 用户可设置每日热量、碳水、蛋白质和脂肪目标，并保存到本地。
- **实现范围：**

  - 显示单位 kcal/g，支持清空/恢复默认。
- **不包含：** 根据身高体重自动计算目标。
- **验收标准：**
  - 输入无效值（空、负数、超大值）有明确提示且不能保存。
  - 变更后首页和新日期使用新目标，历史日期仍可读取当时的目标。
- **测试：** 表单边界、目标按生效日期解析、持久化恢复。

### T06｜实现日汇总 Use Case

- **优先级：** P0
- **预估：** 1 人日

## Sprint B：LLM 图片识别闭环

### T13｜实现 LLM 连通性测试 Use Case

- **优先级：** P1
- **预估：** 1.5 人日
- **前置：** T11、T12
- **目标：** 在设置页以最小请求验证用户的服务地址、模型和密钥是否可用。
- **实现范围：**
  - 定义 HTTP 客户端、超时和错误映射（网络、401/403、429、5xx、解析失败）。
  - 发送不含用户照片的最小文本/能力检测请求；结果以“连接成功/失败原因/建议操作”展示。
  - 日志只记录请求耗时、状态分类，永不记录授权头或正文密钥。
- **不包含：** 食物图片上传、识别结果解析。
- **验收标准：**
  - 各类已知失败均有非技术化中文提示。
  - 连通性测试不会写入餐食数据库或上传本地图片。
- **测试：** Mock HTTP 覆盖成功、超时、401、429、5xx、畸形响应。

### T15｜实现图片预处理与本地图片文件管理

- **优先级：** P0
- **预估：** 2 人日
- **前置：** T14
- **目标：** 以隐私优先方式生成适合识别的上传图片，并可靠保存用户确认后的原图/处理图。
- **实现范围：**
  - 默认删除 EXIF（尤其定位信息）；按配置缩放与压缩副本。
  - 区分临时草稿目录和已保存餐食目录；生成不可猜测的文件名。
  - 提供复制、读取缩略图、删除、清理过期草稿接口。
  - 不在 UI isolate 执行大图压缩，保证页面可交互。
- **不包含：** 网络上传、图片编辑滤镜。
- **验收标准：**
  - 处理后的图片无 GPS EXIF；原图不被原地修改。
  - 保存记录后图片可显示；取消/清理草稿后临时文件可释放。
- **测试：** 给定带 EXIF 图片的处理测试、文件迁移/删除测试、大图手动性能测试。

### T16｜实现通用 LLM 餐食识别适配器与 Schema 校验

- **优先级：** P0
- **预估：** 3 人日
- **前置：** T02、T12、T13、T15
- **目标：** 将预处理图片发给用户配置的视觉模型，并安全转为可编辑餐食草稿。
- **实现范围：**
  - 实现 OpenAI Chat Completions 兼容请求适配器，图片采用服务支持的输入格式。
  - 使用固定、版本化的提示词，要求返回指定 JSON：餐名、食材、重量、热量、三大营养素、置信度、备注。
  - 实现 JSON Schema/手工强校验：字段类型、数值非负、项目至少一项、数量上限、字段缺失容错。
  - 对合规结果创建领域 `MealDraft`；总计强制由食材计算。
  - 对模型异常输出返回可诊断但不泄露原始敏感内容的错误。
- **不包含：** 结果确认 UI、自动重试修复请求、特定供应商私有协议。
- **验收标准：**
  - 对正常、Markdown 包裹 JSON、缺字段、负数、空数组、非 JSON 这六类 mock 响应有确定行为。
  - 用户图片只发送给配置中的 Base URL，授权头不写日志。
  - 得到的草稿可交给 T17 编辑，且总营养与食材一致。
- **测试：** Mock HTTP + fixture 覆盖上述六类响应及网络错误；提示词版本单测快照。

### T17｜实现“AI 结果确认与保存”页

- **优先级：** P0
- **预估：** 3 人日
- **前置：** T08、T16
- **目标：** 用户在 AI 识别后查看、修改并明确确认餐食，才写入本地数据库。
- **实现范围：**
  - 图片预览、餐次选择、餐名、份数、总热量、三大营养素、食材编辑复用 T08 组件。
  - 显示“AI 估算，仅供饮食记录参考”和置信度/不确定性提示。
  - 保存时创建餐食、移动图片文件、更新日汇总；失败时保留草稿并给出重试。
  - 支持“重新识别”“改为手动编辑”“放弃草稿”。
- **不包含：** 多图识别、离线模型。
- **验收标准：**
  - AI 输出不会未经用户确认自动保存。
  - 用户编辑任一食材后总计实时重算；保存后首页正确刷新。
  - 网络失败/离开页面时图片与草稿不丢失，也不会留下无关联的正式图片。
- **测试：** Widget 测试编辑重算、保存成功/失败、放弃；真机跑通“拍照→识别→修改→保存”。

## Sprint C：数据自主、兼容和发布质量

### T18｜实现本地数据导出（JSON/CSV）

- **优先级：** P1
- **预估：** 2 人日
- **前置：** T04、T12、T15
- **目标：** 用户可在本地导出自己的饮食数据，且导出物不泄露密钥。
- **实现范围：**
  - JSON 导出完整餐食/食材/目标数据，带 schema version 和生成时间。
  - CSV 导出食材级明细；数值与日期格式稳定。
  - 图片默认不导出，提供“包含图片”的明确二次确认（如该能力本期实现）。
  - 调用平台分享/保存接口，处理用户取消。
- **不包含：** 数据导入、云同步、导出 API Key。
- **验收标准：**
  - 导出内容可在文本工具打开且结构正确，绝不含 API Key。
  - 无记录时给出友好提示，不生成无意义文件。
- **测试：** fixture 导出快照、CSV 转义（逗号/换行）、敏感字段不存在断言。

### T19｜实现本地数据清除与隐私说明页

- **优先级：** P0
- **预估：** 1.5 人日
- **前置：** T03、T11、T15
- **目标：** 用户可以明确理解数据去向，并可清除餐食数据、图片和 LLM 配置。
- **实现范围：**
  - 隐私说明：无账号/无自有云端、图片会直发至用户选择的模型服务、API Key 安全存储、导出包含健康数据。
  - “清除饮食数据”“清除 LLM 配置”“清除全部本地数据”三项操作。
  - 每项二次确认，明确列出会删除的内容；完成后回到干净的首次状态。
- **不包含：** 已上传至第三方 LLM 的远端删除请求。
- **验收标准：**
  - 清除全部后数据库记录、图片文件、草稿和安全存储密钥均不可读取。
  - 单独清除饮食数据不会清除 LLM 配置；单独清除配置不会删除餐食。
- **测试：** 三种清除范围、取消确认、重复清除、重启后验证。

### T20｜无障碍、深色模式与错误状态收尾

- **优先级：** P1
- **预估：** 2 人日
- **前置：** T07、T09、T10、T12、T17、T18、T19
- **目标：** 使 MVP 在常见可用性与错误场景下达到可发布基线。
- **实现范围：**
  - 审核核心页面语义标签、焦点顺序、动态字体、触控面积、颜色对比度。
  - 完成深色主题或至少确保深色系统下不出现不可读内容（以产品决定为准）。
  - 统一空状态、网络错误、权限拒绝、未配置 LLM、保存失败文案与重试入口。
  - 增加全局未捕获异常的本地安全处理，禁止写出敏感内容。
- **不包含：** 新功能、行为分析 SDK。
- **验收标准：**
  - 在最大系统字体下，今日页、编辑页、设置页没有关键文案截断或无法触达操作。
  - 读屏可说出主要按钮、营养数值和错误原因。
  - 无网、拒绝相机、无 LLM 配置时仍能手动记餐，且用户知道下一步。
- **测试：** iOS VoiceOver / Android TalkBack 手测、深浅主题截图、最大字体真机回归。
